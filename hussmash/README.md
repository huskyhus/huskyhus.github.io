# ハススマッシュ（プロトタイプ）

2〜4 人で遊ぶ、スマホ横持ちの対戦アクションです。ギミックのない 1 枚の台の上で、相手を画面の外までふっとばし合います。
HTML / CSS / JavaScript だけで動く静的サイトで、通信は [PeerJS](https://peerjs.com/) 1.5.4（MIT ライセンス、`vendor/` に同梱）の公開サーバーで WebRTC の P2P 接続を張り、
それ以降の通信はすべてその P2P 接続の中で行います。

## 遊び方

| 操作 | スマホ | PC |
| --- | --- | --- |
| 移動 | 画面の左側をさわってぐりぐり（さわった所がスティックの中心） | ←→ / AD |
| ジャンプ | スティックを上へはじく / ジャンプボタン（空中でもう 1 回） | Space / ↑ / W |
| 急降下 | 空中でスティックを下へ | ↓ / S |
| 技 | 右側の A / B / X / Y | L = A、K = B、I = X、J = Y（キーボード上でもひし形の並び） |

- 撃墜されるとストックが 1 つ減ります。% が高いほどよく飛びます。最後までストックが残った人の勝ち
- 場外から台のふちまで戻ると、自動でよじ登ります（崖つかまりの代わり）
- 技は 24 種類（ステッカー 1 枚 = 技 1 つ）。そのうち 4 つをタイトル（またはロビー）の「技を選ぶ」で A / B / X / Y に割り当てます。設定はブラウザに保存されます
- **相手の持ち技は使われるまでわかりません。** 技を使うと頭の上にステッカーが出るので、そこで初めて手の内がばれます。
  カウンターを持っているか、ガードを割るつかみを持っているか、復帰技を捨てて攻撃に振ったか…が読みあいになります
- 技にはそれぞれ再使用までの時間があり、ボタンに暗い円で残り時間が出ます

## 通信

- 「ルームを作る」と 5 桁のルーム番号が出ます。PeerJS の Peer ID は `hussmash-v1-<番号>`。ほかの人は番号を入れて「ルームに入る」
- **ホストが対戦の計算をすべて行い**（[js/sim.js](js/sim.js)）、30 回/秒のスナップショットを配ります。クライアントは入力を 60 回/秒送り、
  届いたスナップショットを約 5 フレーム遅らせて補間して描きます。予測（クライアント側の先読み）はしていないので、クライアントの操作には往復の遅延がそのまま乗ります
- ホストの計算は Web Worker のタイマーで回すので、PC でホストのウィンドウが裏に回っても対戦は止まりません（スマホでブラウザ自体を裏に回すと止まります）
- 通信はロビーも対戦も「状態をまるごと送る」形なので、`reliable: false` で何通か落ちても次の 1 通で元に戻ります。
  ボタンは「押した回数」を送るので、入力が落ちても押したことは伝わります。順番が入れ替わって届いた古いものは番号を見て捨てます
- 対戦中は新しい人は入れません。ロビーでは空いている枠に CPU を入れられます

### 知らない相手への備え（[js/net.js](js/net.js)・[js/protocol.js](js/protocol.js)）

- 接続は `serialization: "raw"` で、届いた生データを自分で検査してから読みます（PeerJS に BinaryPack / JSON の解読や分割データの組み立てをさせない）。
  ホストは `raw` でない接続、`reliable` な接続を開く前に切ります
- 1 通の上限: クライアント → ホスト 1,024 文字、ホスト → クライアント 8,192 文字。文字列でないもの・長すぎるもの・壊れた JSON は捨てます
- 中身は決まった形のフィールドだけを取り出して作り直します。数値は有限・整数・範囲内に丸め、配列は長さを確認、
  名前は制御文字・書字方向の制御文字・`<>` を消して 10 文字まで。技の id は一覧にあるものだけ。画面には `textContent` / Canvas でしか出しません
- 1 接続あたり 150 通/秒を超えた分は捨て、送りすぎる相手と 8 秒黙っている相手は切ります。開きかけの接続は 6 本まで
- ホストのデータも同じように検査します（クライアント側も、ホストが悪意を持っている前提）

## 横向き・拡大の無効化

- `user-scalable=no`、ピンチ・ダブルタップ・ブラウザの拡大キー（Ctrl + / −）・長押しメニュー・スクロールの引っぱりを止めています
- スマホでは最初のボタンを押したときに全画面にし、`screen.orientation.lock("landscape")` で横向きに固定します（Android の Chrome など）。
  iOS の Safari は向きの固定ができないので、縦向きのときは「横向きにしてください」の案内で画面を覆います
- 対戦中は Wake Lock で画面が消えないようにします（対応ブラウザのみ）

## BGM

`musiclab/` と同じ仕組み（音声ファイルを使わず Web Audio で合成）で鳴らします。
`music/` に musiclab の `lib/`（engine / synth / mix / layers / theory / superband）と曲のスケッチ（学園都市のハスタワー・戦闘曲 1 と、学園都市が使うスーパーハスタワー）をそのままコピーしています。
曲を直したときは musiclab で直してから、同じファイルをコピーし直してください。

- タイトル・ロビー: 学園都市のハスタワー / 対戦: 戦闘曲 1「ハスタワー」
- 最初にどこかを押したときから鳴り始めます（ブラウザの自動再生制限のため）。タイトルの「🎵 BGM」「🔊 効果音」でオン / オフ

## ローカルで動かす

ES モジュールを使うため、`file://` で開いても動きません。**このフォルダ（`hussmash/`）** でローカルサーバーを立ててください。

```sh
uv run python -m http.server 8003
```

- http://localhost:8003/ を開き、「練習（CPU と対戦）」なら 1 人で動作を確認できます
- 通信の確認は、同じ PC で 2 つのウィンドウを開いて片方でルームを作り、もう片方で番号を入れて入る
- デバッグ: http://localhost:8003/?debug（コンソールから `hussmash.S`（進行の状態・`S.sim` が対戦）/ `hussmash.renderer` / `hussmash.input` を触れます）
- スマホから試すときは同じ Wi-Fi で `http://<PC の IP>:8003`。全画面・横向き固定・Wake Lock は HTTPS でないと効かないことがあるので、
  本番どおりに試すなら GitHub Pages などに置いてください

## 構成

```
hussmash/
├── index.html
├── css/style.css
├── stickers/          ステッカー画像（husfactory からコピー）。技のアイコン・ボタン・飛び道具に使う
├── avatars/husky.png  ファイターの立ち絵（husmaze の、ステッカーから切り抜いた透過 PNG）
├── vendor/            PeerJS（peerjs.min.js と LICENSE）
├── music/             musiclab からコピーした BGM のエンジンと曲
└── js/
    ├── main.js        画面の流れ・ホスト / クライアントの進行・補間・スマホ向けの調整
    ├── moves.js       技の定義（24 種）
    ├── sim.js         対戦のシミュレーション（物理・当たり判定・飛び道具・撃墜）と CPU
    ├── protocol.js    通信メッセージの検査とサニタイズ
    ├── net.js         PeerJS の接続（ルーム・流量制限・タイムアウト）
    ├── render.js      描画（Canvas 2D）。カメラ・ステージ・ファイター・エフェクト・% 表示
    ├── input.js       仮想スティック・ボタン・キーボード
    ├── bgm.js         BGM（music/ のエンジン）
    └── sfx.js         効果音（Web Audio で合成）
```

## まだやっていないこと（プロトタイプの次に）

- クライアント側の予測（入力遅延を隠す）。今は往復の遅延がそのまま操作に乗ります
- 崖つかまり・受け身・ずらし（DI）・シールドの向きなど、本格的な格闘ゲームの操作
- 接続の確立には PeerJS の既定の ICE サーバー（Google の STUN と PeerJS 公開の TURN）を使います。直接つながらないネットワーク同士では、データが PeerJS の TURN を経由します
