# ハススマッシュ（プロトタイプ）

2〜4 人で遊ぶ、スマホ横持ちの対戦アクションです。ギミックのない 1 枚の台の上で、相手を画面の外までふっとばし合います。
HTML / CSS / JavaScript だけで動く静的サイトで、通信は [PeerJS](https://peerjs.com/) 1.5.4（MIT ライセンス、`vendor/` に同梱）の公開サーバーで WebRTC の P2P 接続を張り、
それ以降の通信はすべてその P2P 接続の中で行います。

## 遊び方

| 操作 | スマホ | PC |
| --- | --- | --- |
| 移動 | 画面の左側をさわってぐりぐり（さわった所がスティックの中心） | ←→ / AD |
| ジャンプ | スティックを上へはじく / ジャンプボタン（空中でもう 1 回） | Space / ↑ / W |
| 急降下 | 空中でスティックを下へ | ↓ / S |
| 技 | 右側の A / B / X / Y | L = A、K = B、I = X、J = Y（キーボード上でもひし形の並び） |

- 撃墜されるとストックが 1 つ減ります。% が高いほどよく飛びます。最後までストックが残った人の勝ち
- 場外から台のふちまで戻ると、自動でよじ登ります（崖つかまりの代わり）
- 技は 23 種類（ステッカー 1 枚 = 技 1 つ。「おまえもな！」は禁止）。そのうち 4 つを A / B / X / Y に割り当てます。設定はブラウザに保存されます
  - 技を選ぶ画面: 左の一覧（攻撃・飛び道具・守り…に分けてある）で技をタップすると、右に性能（速さ・威力・ふっとび・再使用）が出ます。
    右下の「どのボタンに入れる？」で A / B / X / Y を押すとそこに入ります（ほかのボタンに入っていた技なら、そのボタンと中身を入れ替え）。
    タイトルの 4 枚の技をタップすると、その技を見た状態で開きます
- **相手の持ち技は使われるまでわかりません。** 技を使うと頭の上にステッカーが出るので、そこで初めて手の内がばれます。
  カウンターを持っているか、ガードを割るつかみを持っているか、復帰技を捨てて攻撃に振ったか…が読みあいになります
- 技にはそれぞれ再使用までの時間があり、ボタンに暗い円で残り時間が出ます
- 最後の 1 人が決まると結果画面が出ます。左は順位・撃墜・撃墜された数・与えたダメージ。行をタップすると、右にその人の成績
  （相手ごとの与えたダメージと撃墜、技ごとの当てた回数・ダメージ・撃墜、受けたダメージ・自滅）が出ます
  - 「ロビーに戻る」: ホストはルームの全員をロビーへ。ほかの人は自分だけロビーへ戻り、ホストが次の対戦を始めると自動で始まります
  - 撃墜は最後に攻撃を当てた人と技に付きます（誰にも触られずに落ちたら自滅）。はね返した飛び道具は「はね返した技」の成績になります

## 練習・技の研究

- 「練習（CPU と対戦）」で CPU を 1 体入れたロビーが開きます
- CPU の強さはロビーのボタンで「動かない → よわい → ふつう → つよい」と切り替え。**動かない** CPU は何もしないので、技の当たり方・ダメージ・ふっとび方をじっくり試せます
- ストック「∞」にすると撃墜されても減らず、✕ でロビーに戻るまで続きます
- 攻撃が当たると、与えたダメージ（%）がその場に出ます

## CPU の強さ（[js/sim.js](js/sim.js) の `CPU_LEVELS`）

以前の CPU が強すぎたのは、主に次の 2 つのせいでした（CPU どうしを 60 試合戦わせて計測）。

1. **人には無理な速さで守っていた**: 相手が技を出した 1 フレーム目から内部状態を読んで、ガード・カウンター・回避を出していた。
   守りの技の反応は最速 1 フレーム（約 17 ミリ秒）、28% が 6 フレーム（0.1 秒）以内。人の反応は速くても 15〜20 フレームなので、
   出の遅い強攻撃（父は森！は 17 フレーム）を毎回カウンターで返されていた
2. **場外から「おまえもな！」で入れ替えていた**: 場外に出ると入れ替えを最優先で使い、プレイヤーを場外に送っていた（今は技ごと禁止）

ほかに、強さの段階がなく、復帰も毎回完璧でした。今は「相手の技に気づくまでの遅れ」を段階ごとに付けています。

| 段階 | 気づくまで | 守りで返す確率 | 考える間隔 | 復帰技の使い忘れ |
| --- | --- | --- | --- | --- |
| よわい | 32F | 15% | 40〜80F | 40% |
| ふつう（初期値） | 22F | 30% | 24〜50F | 15% |
| つよい | 14F | 45% | 14〜36F | 0% |

計測し直すと、守りの反応はどの段階でも最速 15 フレーム以上（6 フレーム以内は 0%）。同じ技どうしの対戦で、つよい は よわい に 38/40 勝、ふつう に 33/39 勝、ふつう は よわい に 35/39 勝。

## 通信

- 「ルームを作る」と 5 桁のルーム番号が出ます。PeerJS の Peer ID は `hussmash-v<PROTOCOL>-<番号>`（今は v2）。ほかの人は番号を入れて「ルームに入る」
  （[js/version.js](js/version.js) の `PROTOCOL`。通信の形を変えたら上げる。版の違う人どうしは別のルームになり、つながらない）
- バージョン（`VERSION`、今は 0.2.0）はタイトルとロビーに出ます。つながらない・挙動が違うときは、全員のバージョンが同じか見比べてください
  （古いままなら再読み込み。スマホはキャッシュが残ることがあるので、タブを閉じて開きなおす）
- **ホストが対戦の計算をすべて行い**（[js/sim.js](js/sim.js)）、60 回/秒のスナップショットを配ります。相手のキャラは、届いたスナップショットを 3 フレーム遅らせて補間して描きます
- **自分のキャラは予測して、遅れなしで動かします**（クライアントのみ。[js/main.js](js/main.js) の `clientTick` / `reconcile`）
  - クライアントは 1 フレームに 1 つ番号付きの入力を作り、ホストと同じ計算（`Sim.stepSolo`）で自分のキャラだけ先に動かします。入力は直近 10 フレームぶんをまとめて送ります
  - ホストは届いた入力を番号順にちょうど 1 つずつ使います（[js/input.js](js/input.js) の `InputQueue`。揺れを吸収するため 2 フレームぶんためてから使い、
    次がまだ届いていなければ番号を進めずに直前の入力を続ける）。同じ入力の並びで計算するので、邪魔が入らなければホストの結果と予測は一致します
  - ホストはスナップショットに、受け取る人のファイターのまるごとの状態（小数も丸めない）と、使い終わった入力の番号を足して送ります。
    クライアントはその状態を読み込み、まだ使われていない入力をやり直して今の位置を出し直します（照合）。ずれた分は数フレームかけて見た目をなめらかに寄せます
  - 当たり・ダメージ・ふっとび・撃墜を決めるのはホストだけ。予測の中では撃墜せず、相手との当たりも計算しません。
    なので「殴られた」「自分の攻撃が当たって止まった（ヒットストップ）」ときだけ、少し遅れてホストの結果に引き戻されます
  - 遅延 95ms ± 15ms・2% 落ちの模擬では、照合の 98% でずれが 0（場外で誰にも邪魔されない復帰は 99.6% が 0）
- ホストの計算は Web Worker のタイマーで回すので、PC でホストのウィンドウが裏に回っても対戦は止まりません（スマホでブラウザ自体を裏に回すと止まります）
- 通信はロビーも対戦も「状態をまるごと送る」形なので、`reliable: false` で何通か落ちても次の 1 通で元に戻ります。
  入力は直近 10 フレームぶんを毎回送るので、何通か落ちても押したことは伝わります。重複や順番が入れ替わって届いたものは番号を見て捨てます
- 空き枠があれば、対戦中・結果画面でもルームに入れます。その対戦は観戦して、次の対戦から参加します。抜けた人もタイトルにルーム番号が残るので、「ルームに入る」ですぐ入りなおせます
- ✕ ボタン: ホスト（練習も）は対戦をやめてロビーへ戻る（ルームはそのまま）。クライアントはルームから抜ける
- ロビーでは空いている枠に CPU を入れられます
- ホスト以外の人はロビーの「準備OK」を押します（押すたびにオン / オフ。ホスト自身と CPU はいつも準備OK）。全員が準備OK になると、ホストが「対戦開始！」を押せます。
  準備OK は対戦のあとも残るので、結果画面の「もう一度」もそのまま押せます（ロビーに戻って準備OK を外した人や、途中から入った人がいると押せない）
- 結果画面の間にロビーで変えた名前・技は次の対戦に使われます（カウントダウンと対戦の間だけは変わらない）

### 知らない相手への備え（[js/net.js](js/net.js)・[js/protocol.js](js/protocol.js)）

- 接続は `serialization: "raw"` で、届いた生データを自分で検査してから読みます（PeerJS に BinaryPack / JSON の解読や分割データの組み立てをさせない）。
  ホストは `raw` でない接続、`reliable` な接続を開く前に切ります
- 1 通の上限: クライアント → ホスト 1,024 文字、ホスト → クライアント 8,192 文字。文字列でないもの・長すぎるもの・壊れた JSON は捨てます
- 中身は決まった形のフィールドだけを取り出して作り直します。数値は有限・整数・範囲内に丸め、配列は長さを確認、
  名前は制御文字・書字方向の制御文字・`<>` を消して 10 文字まで。技の id は一覧にあるものだけ。画面には `textContent` / Canvas でしか出しません
- 1 接続あたり 150 通/秒を超えた分は捨て、送りすぎる相手と 8 秒黙っている相手は切ります。開きかけの接続は 6 本まで
- ホストのデータも同じように検査します（クライアント側も、ホストが悪意を持っている前提）

## 横向き・拡大の無効化

- `user-scalable=no`、ピンチ・ダブルタップ・ブラウザの拡大キー（Ctrl + / −）・長押しメニュー・スクロールの引っぱりを止めています
- スマホでは最初のボタンを押したときに全画面にし、`screen.orientation.lock("landscape")` で横向きに固定します（Android の Chrome など）。
  iOS の Safari は向きの固定ができないので、縦向きのときは「横向きにしてください」の案内で画面を覆います
- 対戦中は Wake Lock で画面が消えないようにします（対応ブラウザのみ）

## BGM

`musiclab/` と同じ仕組み（音声ファイルを使わず Web Audio で合成）で鳴らします。
`music/` に musiclab の `lib/`（engine / synth / mix / layers / theory / superband）と曲のスケッチ（学園都市のハスタワー・戦闘曲 1 改と、学園都市が使うスーパーハスタワー）をそのままコピーしています。
曲を直したときは musiclab で直してから、同じファイルをコピーし直してください。

- タイトル・ロビー: 学園都市のハスタワー / 対戦: 戦闘曲 1 改「ハスタワー」
- 最初にどこかを押したときから鳴り始めます（ブラウザの自動再生制限のため）。タイトルの「🎵 BGM」「🔊 効果音」でオン / オフ

## ローカルで動かす

ES モジュールを使うため、`file://` で開いても動きません。**このフォルダ（`hussmash/`）** でローカルサーバーを立ててください。

```sh
uv run python -m http.server 8003
```

- http://localhost:8003/ を開き、「練習（CPU と対戦）」なら 1 人で動作を確認できます
- 通信の確認は、同じ PC で 2 つのウィンドウを開いて片方でルームを作り、もう片方で番号を入れて入る
- デバッグ: http://localhost:8003/?debug（コンソールから `hussmash.S`（進行の状態・`S.sim` が対戦）/ `hussmash.renderer` / `hussmash.input` を触れます）
- スマホから試すときは同じ Wi-Fi で `http://<PC の IP>:8003`。全画面・横向き固定・Wake Lock は HTTPS でないと効かないことがあるので、
  本番どおりに試すなら GitHub Pages などに置いてください

## まだやっていないこと（プロトタイプの次に）

- クライアント側の予測（入力遅延を隠す）。今は往復の遅延がそのまま操作に乗ります
- 崖つかまり・受け身・ずらし（DI）・シールドの向きなど、本格的な格闘ゲームの操作
- 接続の確立には PeerJS の既定の ICE サーバーを使います。PeerJS 公開の TURN（`eu-0` / `us-0.turn.peerjs.com`）は名前解決できず止まっているので、
  実際に使えるのは STUN だけです。直接つながらないネットワーク同士（モバイル回線どうしなど）では、つながりません
