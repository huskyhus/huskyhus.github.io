# 数学科のための制御工学（Web 講義）

このリポジトリは、制御工学の標準カリキュラムを数学科の大学院生以上に向けて 105 分で講義する教材を、HTML/CSS/JS の Web ページとして作るためのもの。ただし表現は動きを伴ったスライドとして見せて、ページのスクロールは行わない。また、ユーザーがスライドバーなどで様々なデータを入力し、リアルタイムで出力結果を見れるようなスライドを目指す。

## 1. 正となる資料

- 講義の中身の正は `sketch.md`（Claude Docs の「数学科のための制御工学 — 105分講義スケッチ」を Markdown で書き出したもの）。
- 数値はすべてPython で再計算して確かめる。uvがあるのでそれを使う。

## 2. 聴き手と前提

- 聴き手：数学科の大学院生以上。線形代数（ジョルダン標準形まで）、常微分方程式の基本定理、複素関数論（留数定理、偏角原理）は既知とする。物理はニュートンの運動方程式が書ける程度。
- 削るもの：ブロック線図の等価変換、ボード線図の手書き規則、根軌跡の作図規則。これらは「作図と計算の技法」であって、数学的な中身ではない。
- 残すもの：ナイキスト判別法（偏角原理からの証明）、可制御性の階数条件、極配置、分離定理、LQR（平方完成による最適性の証明）、ボードの感度積分。数学科の聴き手にとってはここが入口になる。
- 扱わないもの：離散時間系とサンプリング、非線形制御の設計、確率的な状態推定、MPC、H∞ 制御の本体。講義の中では名前も挙げない。唯一の例外は第5部の終わりで、LQR の安定余裕がオブザーバを挟むと失われることを述べるために、カルマンフィルタと LQG の名前だけを「範囲外」と明示して出す。
- 到達目標は「制御工学の地図を渡すこと」。設計の勘を得ることは目的とせず、単に理論のみの速習にフォーカスする。

## 4. 記法

- 時刻 t ≥ 0、複素変数 s、虚数単位は j（工学の慣習）。
- ベクトルは縦ベクトル、ᵀ は転置。σ(A) は A の固有値の集合、ℂ₋ = {Re s < 0}。
- 状態 z、入力 u、出力 y、行列 A, B, C, D。オブザーバゲインは H（L はループ伝達関数に使うので使わない）。
- 数式は KaTeX で組む。

## 5. 未定義語を出さない規則（最重要）

すべての制御用語は、下の表の場所より前に出してはいけない。場面を追加・並べ替えしたら、必ずこの表と照らし合わせる。違反は内容の誤りとして扱う。対象は講義本体（第1部からまとめまで）と、スライドの文字、図のタイトル、ナレーション原稿のすべて。`sketch.md` の冒頭の「この講義の前提」「標準カリキュラムと本講義の目次」は講師向けのメモなので対象外とする。`scripts/check_terms.py` で機械的に確かめられる。

用語の使い方で決めたこと：

- ゲインは定義11で「信号に掛ける倍率」として定義する（k_p, k_i, k_d は比例・積分・微分ゲイン）。定義12の |G(jω)| は「周波数 ω でのゲイン」として同じ語の特別な場合と位置づける。
- 開ループは定義2の意味（入力を前もって決める制御）だけで使う。ループを閉じる前の L のことは「ループ伝達関数 L」と言い、「開ループ L」「開ループが不安定」とは言わない。
- 「周波数」は日常語として定義なしで使ってよい。「比例制御」は使わず「k_d = 0 の PD 制御」と言う。「デケード」は使わず「ω が10倍になるごとに」と言う。
- 部や章の冒頭で、その部の結論を先取りして述べない。冒頭の要約は後で定義する語を呼び込みやすいため。
- 部・章・場面の見出し（題）は例外として、これから定義する語を題に含めてよい（例：「第2部 線形系の解、安定性、伝達関数」）。地の文、スライドの本文、図のタイトル、ナレーションでは例外を認めない。
- 平衡点からのずれは「ずれ」と言い、「偏差」とは言わない。偏差は定義8の e = r − y にだけ使う。

## 6. 通しの例：台車型倒立振り子

パラメータ：M = 1 kg、m = 0.1 kg、ℓ = 0.5 m、g = 9.8 m/s²。z = (x, ẋ, θ, θ̇)ᵀ。θ は鉛直上向きから測る。

本文と図はすべて下の値に揃える。値を変えるときは、全部の図と文を同時に更新する。

| 量                                       | 値                                                                                          |
| ---------------------------------------- | ------------------------------------------------------------------------------------------- |
| p² = (M+m)g/(Mℓ)                         | 21.56、p ≈ 4.64 s⁻¹                                                                         |
| b = 1/(Mℓ)                               | 2                                                                                           |
| A の固有値                               | 0（2重）、±p                                                                                |
| P_θ(s)                                   | −b/(s² − p²)                                                                                |
| P_x(s)                                   | (s² − g/ℓ)/(M s²(s² − p²))、右半平面の零点 √(g/ℓ) ≈ 4.43                                    |
| PD 制御 C(s) = −(k_p + k_d s)            | k_p = 43、k_d = 4。安定条件は k_d > 0 かつ k_p > (M+m)g = 10.78                             |
| PD の閉ループ特性多項式                  | s² + 8s + 64.44（ω_n ≈ 8.0、ζ ≈ 0.50）                                                      |
| ステップ応答（ζ = 0.5、ω_n = 8）         | 行き過ぎ量 約16%（t ≈ 0.45 s）、2% 整定時間 約1.01 s（連続時間で計算）                      |
| L(s) = 2(43 + 4s)/(s² − 21.56)           | L(0) ≈ −3.99、ω_c ≈ 9.7 rad/s、位相余裕 ≈ 42°、ループのゲイン（k_p と k_d を同じ倍率で）を約0.25倍（−12 dB）より下げると不安定 |
| PD を非線形モデルに適用、θ(0) = 0.2 rad  | θ は 0 に戻るが、台車は約 0.26 m/s で流れ続ける（8 秒で x ≈ 2.15 m）                        |
| 可制御性行列                             | \|det 𝒞\| = g²/(M⁴ℓ⁴) = 1536.64                                                             |
| 可観測性                                 | y = x なら可観測（階数4）、y = θ なら階数2                                                  |
| 極配置 {−2, −3, −4, −5}                  | K ≈ (−6.12, −7.86, −49.34, −10.93)                                                          |
| LQR：Q = diag(10, 1, 100, 1)、R = 1      | K ≈ (−3.16, −4.43, −39.58, −8.48)、閉ループ固有値 −5.17 ± 1.72j、−1.10 ± 0.94j              |
| LQR を非線形モデルに適用、θ(0) = 0.2 rad | x の最大 ≈ 0.346 m（t = 0.9 s）、\|u\| の最大 ≈ 7.9 N、約4秒でほぼ原点                      |
| 感度積分の右辺                           | πp ≈ 14.6（ℓ = 0.25 m にすると p ≈ 6.57、πp ≈ 20.6）。微分に時定数 0.02 s のフィルタを掛けた PD で左辺を数値積分すると 14.587 で一致 |
| x だけを測るときの下界                   | ‖S‖∞ ≥ \|(z+p)/(z−p)\| ≈ 42                                                                 |

## 7. 図とアニメーション

スケッチにある静止図（すべて Web 版で SVG として作り直す）：

1. 台車型倒立振り子の模式図
2. A の固有値の配置（ℂ₋ を塗る、+p を強調）
3. 標準フィードバック系のブロック線図（r, e, C, u, d, P, y）
4. 2次系のステップ応答（行き過ぎ量、±2% の帯、整定時間）
5. L のボード線図（ω_c と位相余裕）
6. L のナイキスト線図（−1 を反時計回りに1周、ω = 0 の点、|L| = 1 の点）
7. LQR を非線形の振り子に掛けたシミュレーション（θ と x）

Web 版で動かすもの（優先度順）：

1. 振り子のアニメーション。PD では台車が流れていき、LQR では戻ってくる、という対比を見せる。LQR 側は図7の数値解、PD 側は同じ初期値 θ(0) = 0.2 rad で非線形モデルに PD を掛けた数値解（§6 の表）を使う。
2. k_p のスライダーで閉ループ極が動く根軌跡。
3. ω のスライダーで、点 L(jω) がナイキスト曲線をたどり、同時にボード線図上の縦線が動く連動表示。
4. ループのゲイン（k_p と k_d を同じ倍率で）を 0.25 倍より下げたときに周回が外れて不安定になる瞬間。

図の作り方：

- 色は灰色を基本にして、強調は1色だけ。意味の決まった色（不安定 = 赤など）は全図で統一する。
- 図のタイトルには、その図から読み取ってほしい結論を数値つきで書く（例：「位相余裕 約42°」）。
- データは Python で計算した JSON から描く。SVG に数値を手で打ち込まない。

## 8. 技術方針

- 素の HTML/CSS/JS で作る。ビルド工程は最小限にし、`index.html` をブラウザで開けば動く状態を保つ。
- KaTeX とその数式フォントはリポジトリに同梱する（CDN に頼らない。オフラインでも表示できること）。日本語の本文フォントは同梱せず、端末のフォント（ヒラギノ、游ゴシック、メイリオなど）を使う。
- 1場面 = 1つのデータ単位にする。場面の並び、表示する図、テキスト、ステップ（クリックで進む区切り）を `content/scenes/*.json`（または同等の構造）で管理する。場面の追加・削除・並べ替えは、このデータを編集するだけで済むようにする。
- ナレーションの原稿は `content/narration/` に章ごとに置く。原稿の段落はステップと1対1に対応させ、ID（`ch1/s03/2` = 章/場面/ステップ）で場面データと結びつける。原稿の書式は `content/narration/README.md` に書く。
- 読み上げはブラウザの音声合成（Web Speech API）で行い、原稿の `yomi` を渡す。声は端末に入っている日本語の声（Windows の Nanami・Haruka、macOS の Kyoko など）で、端末によって変わる。音声ファイルは持たない。
- 将来ずんだもんなどの音声ファイルを使う場合は、`window.AUDIO_FILES = { "ch1/s03/2": "audio/...", ... }` を定義する JS を読み込めば、そのステップはファイルを優先して鳴らす（無いステップはブラウザの音声合成のまま）。
- 将来 mp4 が必要になったら、Remotion や Motion Canvas、あるいはヘッドレスブラウザでの画面収録で書き出す。今は対応しないが、その道を塞ぐ設計（手作業前提のアニメーションなど）は避ける。
- 数値計算は `scripts/`（Python、numpy/scipy）に置き、出力 JSON を `data/` に保存する。図とアニメーションは `data/` だけを読む。ただし、スライダーで値を変えたときの再計算はブラウザ側で行う（既定値のときは `data/` の値を使う）。
- `index.html` を file:// で開くと JSON を fetch できないので、生成物は `.json` と同じ内容の `.js`（`window.DATA` / `window.NARRATION` への代入）を両方書き出し、ページは `.js` を `<script>` で読む。生成物は手で編集しない。

生成と検査（原稿・数値を変えたら実行する）：

```
uv run scripts/build_narration.py   # content/narration/ch*.md → narration.js
uv run scripts/build_data.py        # data/*.json, data/*.js
uv run scripts/verify_numbers.py    # §6 の数値を再計算して表示
uv run scripts/check_terms.py       # 用語の順序、表の一致、範囲外の語
```

画面の検査：`index.html?check` を開くと、全場面の最後のステップを順に表示して、字幕や画面外へのはみ出し、KaTeX の誤り、速く送ったときに場面が残らないかを調べ、結果を画面に出す。ヘッドレス Chrome なら `chrome --headless=new --window-size=1600,1000 --virtual-time-budget=20000 --dump-dom "file:///.../index.html?check"` の出力の `<pre id="check-report">` を見る。

場面データの書き方：`content/scenes/<章>.js` で `LECTURE.chapter({ id, scenes: [...] })` を呼ぶ。場面は `{ id, layout, blocks }`、layout は `title` / `full` / `split`（左右2段）。ブロックは `type`（title, subtitle, h, p, note, quote, list, math, def, fig, html）、`at`（現れるステップ）、`until`、`dimAfter`、`area`（left / right）を持つ。数式は `$...$` と `$$...$$`。図は `src/figures.js` の `FIG.<名前>` を `{ type: "fig", name, opts }` で呼ぶ。場面の並びとステップ数はナレーション原稿（`content/narration/`）が決め、場面データの無い場面は原稿をそのまま本文として表示する。

用語集：`content/glossary.js` に、用語ごとの定義（`def`）、工学的な意味（`meaning`）、定義したステップ（`at`）を書く。G キーか「用語」ボタン、スライド中の太字の用語のクリックでモーダルが開く。既定では今のステップまでに定義した用語だけを出す。§5 の表に用語を足したら用語集にも足す。`check_terms.py` が次を確かめる：表の語がすべてあること、`at` の原稿にその語が出ること、説明文にその項目より後で定義する語を使っていないこと。

操作：→ / Space / クリックで進む、← で戻る、M 目次、G 用語集、S 字幕、A 読み上げ、P 自動送り（読み上げが終わったら次へ。読み上げが無ければ読みの文字数から時間を決める）、F 全画面。下の帯で声と速さを選べる（選択はブラウザに保存）。URL の `#ch1/s03/2` でそのステップを直接開ける。

想定するディレクトリ構成（必要に応じて調整してよいが、変えたらここを更新する）：

```
sketch.md        講義スケッチ（正）
content/scenes/       場面データ
content/narration/    ナレーション原稿（章ごとの Markdown）
content/glossary.js   用語集（定義、工学的な意味、定義したステップ）
audio/                ナレーション音声（後から追加）
data/                 計算結果の JSON
scripts/              数値計算と検査（Python、uv run で実行）
src/                  JS（場面の再生、図の描画、スライダー）
styles/               CSS
vendor/               KaTeX、フォント
index.html
```

## 9. 文章の書き方（AI っぽさを出さない）

- 段落の最初の一文に結論を置く。ただし §5 の規則が優先で、まだ定義していない語を使う結論は先に書かない。部や章の冒頭では結論を先取りしない。
- 決まった締めの言い回しを使わない：「〜と言えるでしょう」「いかがでしたか」「重要です」「ぜひ」など。
- 同じ型を繰り返さない。「A ではなく B」で問いを立て、「つまり」で言い換え、型どおりに締める流れを段落ごとに繰り返すと、AI っぽく見える。
- 三つ組の列挙、「X だけでなく Y も」、太字の多用、箇条書きの多用を避ける。定義・定理のラベル以外は地の文で書く。
- 形容詞の代わりに数値を書く（「速く倒れる」ではなく「約0.22秒ごとに e 倍」）。
- 文体は「である」調。講義の地の文として、声に出して読める長さに保つ。
- 原稿を書いたら、声に出して読む前提で読み返し、引っかかる箇所を削る。

## 10. 作業の進め方

- 変更は小さく分けてコミットする。場面1つ、または図1枚が目安。
- 図や場面を変えたら、ブラウザで実際に開いて確認する。可能ならスクリーンショットで、文字の重なりやはみ出しを確かめる。
- 数値を変えたら `scripts/` を再実行し、§6 の表と本文を同時に更新する。
- 用語を新しく使ったら §5 の表を確認する。
- 不明点は推測で埋めず、ユーザーに聞く。

## 11. 最初の作業

1. `sketch.md` があるか確認する。無ければユーザーに依頼して止まる。（済）
2. §6 の数値をすべて `scripts/` で再計算し、食い違いがあれば報告する。（済：`scripts/verify_numbers.py`）
3. 章の分け方（§3）をユーザーと決める。（済）
4. 骨組みを作る：`index.html`、場面データの形式、場面を進める仕組み、KaTeX の同梱。（済）
5. 第1部（振り子の模式図と線形化）を1章として完成させ、ユーザーに確認してもらってから次の部に進む。（済）
6. ナレーション原稿は全章の初稿がある（`content/narration/`）。音声化の前に読み返して直す。
7. 全章のスライドの初版がある（`content/scenes/`）。§7 の「Web 版で動かすもの」1〜4 はすべて実装済み（ch5b/s05、ch3/s09、ch4/s08 の ω とゲインのスライダー）。
