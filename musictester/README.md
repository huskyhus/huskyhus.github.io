# musictester

コード進行を組み立て、メロディやベースを「ガチャ」で生成しながら、耳で作曲と機能和声を学ぶ Web ツールです。
HTML / CSS / JavaScript だけで動きます。ライブラリも音声ファイルも使わず、音はすべて Web Audio API で合成します。

## 動かす

ES モジュールを使うので、`index.html` を直接開いても動きません。このフォルダでローカルサーバーを立ててください。

```sh
node tools/serve.js        # http://localhost:8010/ （別のポートなら node tools/serve.js 8020）
```

Node がなければ `python -m http.server 8010` でも構いません。

## テスト

```sh
npm test                   # または node tests/run.js
```

ブラウザで動かすときは http://localhost:8010/tests/index.html を開きます（同じテストが動きます）。

## 使い方

1. 左のパレットからコードのタイルを小節へドラッグします。タイルを押して試聴し、続けて小節を押しても置けます。
2. 「次のコードの候補」と「有名なコード進行」を参考に進行を作り、「理論ガイド」でどう聞こえるかを確かめます。
3. 「パートとミキサー」でガチャを引きます。気に入ったパートはロックします。◀ で前の結果に戻せます。
4. セクションを増やし、タブを「曲の構成」へドラッグして曲にします。
5. 「保存 / 読込」で JSON に書き出せます。作業中のデータはブラウザに自動保存されます。

Space キーで、選択中のセクションの再生と停止を切り替えられます。

## 曲の JSON（スキーマ v1）

```jsonc
{
  "format": "musictester-song",
  "schemaVersion": 1,
  "title": "無題",
  "settings": { "key": { "tonic": 0, "mode": "major" }, "bpm": 120 },   // tonic: C=0 〜 B=11
  "sections": [{
    "id": "s1",
    "name": "A",
    "bars": [                                     // 常に 8 要素。1 小節に複数のコードを持てる形
      { "chords": [{ "startBeat": 0, "beats": 4, "chord": { "kind": "scale", "deg": 5, "size": 4, "harmonic": true } }] }
    ],
    "parts": {                                    // melody / bass / drums / counter / harmony
      "melody": {
        "locked": false,
        "seed": 12345,
        "params": { "density": 0.5, "low": 62, "high": 81, "style": "lyrical" },
        "notes": [{ "t": 0, "d": 4, "midi": 72, "v": 0.85 }],   // t, d は 16 分音符単位。ドラムは midi の代わりに "drum": "kick"
        "basis": "…",                             // 生成時のコード進行の印。今の進行と違えば「引き直し」の表示を出す
        "history": [{ "seed": 12345, "params": {}, "notes": [], "basis": "…" }],
        "historyIndex": 0
      }
    }
  }],
  "arrangement": ["s1", "s1"],                    // 曲 = セクション id の並び
  "mix": { "master": 0.8, "parts": { "chords": { "volume": 0.6, "mute": false, "solo": false, "timbre": "pad" } } }
}
```

コードはコード名ではなくディグリーで保存します。調を変えても `settings.key` を変えるだけで、コード名は表示のたびに計算します。

| `kind` | 内容 | フィールド |
| --- | --- | --- |
| `scale` | その調の音階の上の和音。種類は調から決まる | `deg`（1〜7）、`size`（3 か 4）、`harmonic`（短調で V と vii° を和声短音階の形にする） |
| `sec` | セカンダリードミナント | `target`（行き先の度数）、`size` |
| `abs` | 種類が固定の和音（借用和音など） | `semi`（主音からの半音）、`letter`（音名の進み）、`quality` |

次の 2 つは省略できます。

- コードの `inversion`（1〜3）: 転回形。構成音の何番目を低音にするか。G/B なら 1、C7/G なら 2、Am7/G なら 3。
- セクションの `note`（文字列）: 進行の説明。編集画面の小節の上に表示します。

スキーマを変えるときは `SCHEMA_VERSION` を上げ、`song.js` の `migrate` に古い形からの変換を書きます。

## 収録している曲のデータ（songs/）

「保存 / 読込」から読み込める、コード進行だけのデータです（パートは空なので、ガチャで生成できます）。musiclab の楽譜から変換しました。

- `songs/hustower-super.json`: スーパーハスタワー（C メジャー・124 BPM・46 小節）
- `songs/hustower-battle-kai.json`: 戦闘曲 1 改（A マイナー・160 BPM・140 小節）

今のサイトの仕組みに合わせたため、次の点が原曲と違います。

- 調は曲全体で 1 つなので、大サビの転調先のコードは主調から見た `abs` で表しています。コード名と音は正しいですが、ディグリーと機能は主調から見たものです。転調先での度数は `note` に書きました。
- セクションは 8 小節固定なので、4 小節の前奏などの残りは空き小節です。曲全体を再生すると、そこは無音になります。10 小節・12 小節の大サビは 2 つに分けました。
- 原曲の「イントロは最初の 1 回だけ」とループ先、前奏のテンポ変化は表せません。

## 理論の扱いで決めたこと

- **短調のディグリー表記:** 同主長調を基準に数えます（i, ii°, ♭III, iv, v, ♭VI, ♭VII）。
- **長調 ⇄ 短調の移調:** 音階の同じ度数の和音にします。カノン進行は C では C–G–Am–Em–F–C–F–G、A マイナーでは Am–E–F–C–Dm–Am–Dm–E です。長調の V と vii° はドミナントの働きを保つため、短調では和声短音階の形（E, G♯dim）にします。短調のパレットから置いた自然的な v は、長調を往復しても v に戻ります。
- **機能の分類:** 短調の ♭VI は S、♭VII は D、長調に借用した ♭VII は S（サブドミナントマイナー）として扱います。流派によって見方が分かれる和音です。
- **生成済みの音符の移調:** コードの構成音は移した先のコードの同じ番目の音へ、それ以外は音階の度数を保って移します。コード進行そのものを変えたときは自動で作り直さず、「引き直し」の表示を出します。
- **メロディを引き直したとき:** ロックしていない対旋律とハモリは、それぞれのシードのまま新しいメロディに合わせて作り直します。
